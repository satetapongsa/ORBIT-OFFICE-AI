# AURA OFFICE AI — Database Design

PostgreSQL 17 with the `vector` (pgvector) extension. This document is the
target schema. Tables are created incrementally by Alembic migrations in the
phase that needs them (column lists below are the plan; the migration is the
source of truth once written).

## 1. Global conventions

| Rule              | Convention                                                                   |
| ----------------- | ---------------------------------------------------------------------------- |
| Primary keys      | `id UUID` generated by the application (`uuid4`), server default `gen_random_uuid()` |
| Timestamps        | `created_at`, `updated_at` as `TIMESTAMPTZ`, stored in UTC, server defaults `now()` |
| Naming            | `snake_case`, plural table names, FK columns `<entity>_id`                   |
| Constraint names  | deterministic naming convention (`pk_`, `fk_`, `uq_`, `ix_`, `ck_`) set on `MetaData` |
| Enums             | stored as `VARCHAR` + `CHECK` constraint (easier to migrate than native PG enums) |
| Soft delete       | `deleted_at TIMESTAMPTZ NULL` **only** on `users`, `documents`, `tasks`, `tickets`, `departments`; everything else hard-deletes or cascades |
| Money / numbers   | not applicable yet; use `NUMERIC` if introduced                              |
| JSON              | `JSONB` only for genuinely schemaless data (audit metadata, AI tool args)    |
| Text search       | `pg_trgm` indexes for name/title search where needed (Phase 4/5)             |

Migration `0001` enables extensions: `vector`, `pg_trgm`. (`gen_random_uuid()`
is built into PostgreSQL ≥ 13.)

## 2. Identity and access

### `users` (Phase 2)
| column | type | notes |
| --- | --- | --- |
| id | uuid PK | |
| employee_code | varchar(32) | unique — company employee ID |
| email | citext-like `varchar(320)` | unique on `lower(email)` |
| password_hash | varchar(255) | Argon2id; NULL for SSO-only users later |
| first_name, last_name | varchar(100) | |
| display_name | varchar(200) | |

| phone_work | varchar(50) NULL | directory-visible |

| is_active | boolean | login allowed |
| last_login_at | timestamptz NULL | |
| password_changed_at | timestamptz NULL | invalidates older sessions |
| deleted_at | timestamptz NULL | |

Index: `ix_users_department_id`, trigram index on display name (Phase 5).

### `employee_hr_profiles` (Phase 5) — sensitive HR data split out
Separate table so ordinary directory queries can never accidentally select
sensitive columns: `user_id` (PK/FK), `date_of_birth`, `national_id_last4`,
`personal_phone`, `personal_email`, `address`, `hire_date`, `employment_type`,
`emergency_contact` (JSONB). Readable only with `employees:read_sensitive`.

### `roles`, `permissions`, `user_roles`, `role_permissions` (Phase 2)
| table | columns |
| --- | --- |
| `roles` | id, code (unique, e.g. `ADMIN`), name, description, is_system (bool — system roles cannot be deleted) |
| `permissions` | id, code (unique, `domain:action`, e.g. `documents:upload`), description |
| `user_roles` | user_id FK, role_id FK, assigned_by FK users NULL, created_at — PK (user_id, role_id) |
| `role_permissions` | role_id FK, permission_id FK — PK (role_id, permission_id) |

Permissions are seeded by migration/seed script from a code-defined catalogue
(`app/core/permissions.py`, Phase 2) so code and DB stay in sync.

### `user_sessions` (Phase 2) — refresh-token rotation
| column | type | notes |
| --- | --- | --- |
| id | uuid PK | session id (also in access-token `sid` claim) |
| user_id | uuid FK → users ON DELETE CASCADE | |
| family_id | uuid | all rotations of one login share a family |
| refresh_token_hash | char(64) | SHA-256 of the opaque refresh token; unique |
| expires_at | timestamptz | |
| rotated_at / revoked_at | timestamptz NULL | reuse of a rotated token revokes the whole family |
| user_agent, ip_address | varchar / inet NULL | for the user's session list |

### `password_reset_tokens` (Phase 2 architecture)
id, user_id FK, token_hash (unique), expires_at, used_at NULL.

## 3. Documents and RAG

### `documents` (Phase 4)
| column | type | notes |
| --- | --- | --- |
| id | uuid PK | |
| title | varchar(300) | |
| description | text NULL | |
| category | varchar(50) | `POLICY`, `PROCEDURE`, `FORM`, `REPORT`, `CONTRACT`, `MANUAL`, `OTHER` |
| department_id | uuid FK NULL | owning department |
| owner_id | uuid FK → users | uploader / owner |
| visibility | varchar(20) | `PRIVATE`, `DEPARTMENT`, `COMPANY`, `RESTRICTED` (ACL only) |
| status | varchar(20) | `DRAFT`, `ACTIVE`, `ARCHIVED` |
| current_version_id | uuid FK → document_versions NULL | `use_alter` to break the cycle |
| deleted_at | timestamptz NULL | |

### `document_versions` (Phase 4)
id, document_id FK CASCADE, version_number (unique with document_id),
storage_key (unique; never user-controlled), original_filename (sanitised),
mime_type, size_bytes, sha256, uploaded_by FK, processing_status
(`PENDING`, `PROCESSING`, `READY`, `FAILED`), processing_error (text NULL),
page_count NULL, created_at.

### `document_acl` (foundation Phase 2, used Phase 4)
| column | type | notes |
| --- | --- | --- |
| id | uuid PK | |
| document_id | uuid FK CASCADE | |
| principal_type | varchar(20) | `USER`, `DEPARTMENT`, `ROLE` |
| principal_id | uuid | id of the user/department/role |
| access_level | varchar(20) | `VIEW` < `EDIT` < `MANAGE` |
| granted_by | uuid FK users NULL | |

Unique `(document_id, principal_type, principal_id)`; index
`(principal_type, principal_id)` for retrieval-time filtering.

### `document_chunks` (Phase 7)
| column | type | notes |
| --- | --- | --- |
| id | uuid PK | |
| document_id | uuid FK CASCADE | denormalised for fast ACL join |
| document_version_id | uuid FK CASCADE | |
| chunk_index | int | unique with version |
| page_number | int NULL | |
| content | text | cleaned chunk text |
| token_count | int | |
| embedding | `vector(AI_EMBEDDING_DIMENSIONS)` | dimension fixed by migration (default 1024) |
| embedding_model | varchar(200) | model that produced the vector |
| metadata | jsonb | heading, sheet name, etc. |

Index: HNSW `embedding vector_cosine_ops`; btree on `document_id`.
**ACL is not copied into chunks** — retrieval joins `documents` + `document_acl`
at query time so permission changes take effect immediately (see `DECISIONS.md`).
Only chunks of each document's `current_version_id` with `READY` status are
searchable.

## 4. Tasks (Phase 5)

| table | key columns |
| --- | --- |
| `tasks` | id, title, description, status (`TODO`,`IN_PROGRESS`,`REVIEW`,`COMPLETED`,`CANCELLED`), priority (`LOW`,`MEDIUM`,`HIGH`,`URGENT`), due_at NULL, created_by FK, department_id FK NULL, completed_at NULL, deleted_at |
| `task_assignees` | task_id FK CASCADE, user_id FK CASCADE, assigned_by, created_at — PK (task_id, user_id) |
| `task_comments` | id, task_id FK CASCADE, author_id FK, body, created_at, updated_at, edited flag |
| `task_attachments` | id, task_id FK CASCADE, storage_key, original_filename, mime_type, size_bytes, uploaded_by |
| `task_events` | id, task_id FK CASCADE, actor_id, event_type (`CREATED`,`STATUS_CHANGED`,`ASSIGNED`,…), from_value, to_value, created_at — task history |

Indexes: `(status, due_at)` for overdue queries, `task_assignees(user_id)`.

## 5. AI assistant (Phase 6)

| table | key columns |
| --- | --- |
| `chat_sessions` | id, user_id FK CASCADE, title, created_at, updated_at, deleted_at NULL |
| `chat_messages` | id, session_id FK CASCADE, role (`user`,`assistant`,`tool`,`system`), content, citations JSONB (doc id, version id, chunk id, page, title), tool_name NULL, tool_payload JSONB NULL, provider, model, input_tokens, output_tokens, created_at |
| `ai_action_requests` | id, session_id FK, message_id FK NULL, user_id FK, tool_name, arguments JSONB (validated), status (`PENDING`,`CONFIRMED`,`REJECTED`,`EXECUTED`,`FAILED`,`EXPIRED`), result JSONB NULL, expires_at, decided_at, executed_at |

Retention: configurable (`AI_CHAT_RETENTION_DAYS`); a periodic worker purges
expired sessions.

## 7. Notifications and audit (Phase 2/8)

### `notifications`
id, user_id FK CASCADE, type, title, body, link_url NULL, entity_type/entity_id
NULL, read_at NULL, created_at. Index `(user_id, read_at, created_at DESC)`.

### `audit_logs` (Phase 2)
| column | type | notes |
| --- | --- | --- |
| id | uuid PK | |
| occurred_at | timestamptz | indexed |
| actor_id | uuid FK users NULL | NULL for anonymous (e.g. failed login) |
| action | varchar(100) | e.g. `auth.login`, `auth.login_failed`, `document.download`, `role.permission_granted` |
| entity_type / entity_id | varchar / uuid NULL | |
| ip_address | inet NULL | |
| user_agent | varchar(500) NULL | |
| request_id | varchar(64) NULL | correlates with structured logs |
| metadata | jsonb | **never** passwords, tokens, keys or document content |

Append-only: the application has no update/delete path for audit rows.

## 8. Entity relationship summary

```
departments 1─* users *─* roles *─* permissions
users 1─* user_sessions
documents 1─* document_versions 1─* document_chunks
documents 1─* document_acl ─▶ (user | department | role)
tasks *─* users (task_assignees); tasks 1─* task_comments / task_events / task_attachments
users 1─* chat_sessions 1─* chat_messages; chat_sessions 1─* ai_action_requests
tickets 1─* ticket_comments / ticket_events; users 1─* notifications; users 1─* audit_logs
```
